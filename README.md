# Marketing Email Automation MVP

This project is a basic marketing email automation tool.

It can:

- Read a raw customer CSV file
- Filter subscribed users into a clean subscriber CSV
- Read marketing content from a campaign JSON file
- Generate an HTML email preview
- Send HTML emails through SMTP
- Support dry run mode before real sending
- Limit the number of emails sent
- Validate and deduplicate email addresses
- Track sent recipients by campaign to avoid sending the same campaign to the same email twice
- Save sending results to a log file
- Run the full workflow through a unified `main.py` command line entry

## 4. Environment Configuration

Create a `.env` file in the project root.

You can copy from:

```text
.env.example
```

Example:

```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USERNAME=your_email@gmail.com
SMTP_PASSWORD=your_app_password
FROM_EMAIL=your_email@gmail.com
TEST_TO_EMAIL=your_email@gmail.com

DRY_RUN=true
MAX_SEND_LIMIT=3
SEND_DELAY_SECONDS=2

RAW_CUSTOMERS_FILE=data/customers.csv
FILTERED_SUBSCRIBERS_FILE=data/subscribed_only.csv
SUBSCRIBERS_FILE=data/subscribed_only.csv

EMAIL_COLUMN=邮箱
SUBSCRIBE_COLUMN=订阅状态
SUBSCRIBED_VALUE=已订阅

CAMPAIGN_FILE=campaigns/spring_sale_2026/campaign.json
TEMPLATE_FILE=templates/email_template.html
HTML_FILE=output/preview.html
LOG_FILE=output/send_log.csv
RECIPIENT_HISTORY_FILE=output/recipient_history.csv
SUPPRESS_PREVIOUS_SENDS=true
UNSUBSCRIBE_URL=https://example.com/unsubscribe
```

Important settings:

- `DRY_RUN=true` means the script will not really send emails.
- `DRY_RUN=false` means real emails will be sent.
- `MAX_SEND_LIMIT=3` means only the first 3 valid subscribers will be processed.
- `SEND_DELAY_SECONDS=2` means the script waits 2 seconds between each email.
- `RAW_CUSTOMERS_FILE` is the original customer CSV file.
- `FILTERED_SUBSCRIBERS_FILE` is the cleaned subscriber CSV generated by `filter_subscribers.py`.
- `SUBSCRIBERS_FILE` is the CSV file used by `send_bulk_email.py`.
- `EMAIL_COLUMN`, `SUBSCRIBE_COLUMN`, and `SUBSCRIBED_VALUE` allow the script to handle Chinese CSV column names.
- `CAMPAIGN_FILE` controls which campaign JSON file is used.
- `TEMPLATE_FILE` controls which HTML email template is used.
- `HTML_FILE` controls where the generated HTML preview is saved.
- `LOG_FILE` controls where the sending log is saved.
- `RECIPIENT_HISTORY_FILE` controls where per-recipient campaign send history is saved.
- `SUPPRESS_PREVIOUS_SENDS=true` skips emails that have already received the same campaign successfully.

Dry runs do not write successful send records to `recipient_history.csv`, so testing will not block later real sends.

### Preventing Duplicate Campaign Sends

The bulk sender checks `campaign_name + email` before sending.

Example:

```text
On May 1, spring_sale_2026 is successfully sent to alice@example.com.
On May 2, alice@example.com appears again in a new CSV because she browsed the website again.
The script skips alice@example.com for spring_sale_2026.
```

If the campaign changes to something like `summer_sale_2026`, the same email can still receive the new campaign.

Only real successful sends with status `sent` are used for this suppression. `dry_run` and `failed` records do not block future sends.

## 5. Raw Customer CSV Format

The raw customer CSV can contain many columns.

Example:

```csv
姓名,邮箱,累计金额,购买次数,注册时间,订阅状态,业务员
Alice,alice@example.com,100,1,2026-01-01,已订阅,Tom
Bob,bob@example.com,200,2,2026-01-02,未订阅,Tom
Charlie,charlie@example.com,300,3,2026-01-03,已订阅,Amy
Duplicate Alice,alice@example.com,400,4,2026-01-04,已订阅,Amy
Invalid Email,wrong-email,500,5,2026-01-05,已订阅,Tom
Empty Email,,600,6,2026-01-06,已订阅,Amy
```

The filtering script only needs these two columns:

```text
邮箱
订阅状态
```

The matching rules are configured in `.env`:

```env
EMAIL_COLUMN=邮箱
SUBSCRIBE_COLUMN=订阅状态
SUBSCRIBED_VALUE=已订阅
```

If the original CSV uses different column names, update `.env`.

Example:

```env
EMAIL_COLUMN=邮箱地址
SUBSCRIBE_COLUMN=是否订阅
SUBSCRIBED_VALUE=Yes
```

## 6. Filter Subscribed Users

Run with the unified entry:

```bash
python3 main.py filter
```

Or run the script directly:

```bash
python3 src/filter_subscribers.py
```

This will read:

```text
data/customers.csv
```

And generate:

```text
data/subscribed_only.csv
```

Output CSV format:

```csv
email,subscribed
alice@example.com,true
charlie@example.com,true
```

The filtering script will:

- Keep only subscribed users
- Skip empty emails
- Skip invalid emails
- Skip duplicate emails
- Convert email addresses to lowercase
- Output only `email` and `subscribed`

Expected terminal output:

```text
Filter subscribers finished.
--------------------------------------------------
Input file: data/customers.csv
Output file: data/subscribed_only.csv
Total rows: ...
Subscribed users exported: ...
Skipped not subscribed: ...
Skipped empty email: ...
Skipped invalid email: ...
Skipped duplicate: ...
```

## 7. Subscriber CSV Format

The final subscriber CSV should contain:

```csv
email,subscribed
test1@example.com,true
test2@example.com,true
test3@example.com,false
```

Only users with:

```text
subscribed = true
```

will be processed by the sending script.

## 8. Campaign JSON Format

Marketing content is stored in:

```text
campaigns/spring_sale_2026/campaign.json
```

Example:

```json
{
  "campaign_name": "spring_sale_2026",
  "subject": "Spring Sale Gaming PC Deals",
  "preview_text": "Save up to $200 on selected gaming PCs.",
  "logo_url": "https://example.com/logo.png",
  "hero_image_url": "https://example.com/hero.jpg",
  "title": "Spring Sale Gaming PC Deals",
  "subtitle": "Upgrade your setup with limited-time offers.",
  "sections": [
    {
      "heading": "High Performance Gaming PCs",
      "text": "Enjoy smooth gaming, clean cable management, and fast delivery.",
      "image_url": "https://example.com/product1.jpg",
      "button_text": "Shop Now",
      "button_url": "https://example.com/products/gaming-pc"
    },
    {
      "heading": "Limited Time Discount",
      "text": "Selected models are available with special promotional pricing.",
      "image_url": "https://example.com/product2.jpg",
      "button_text": "View Deals",
      "button_url": "https://example.com/collections/sale"
    }
  ],
  "footer_note": "You are receiving this email because you subscribed to our updates."
}
```

Recommended image URL rules:

- Use public `https` image URLs.
- Open each image URL in an incognito browser window to confirm it works.
- Prefer `.png`, `.jpg`, or `.jpeg`.
- Avoid local paths such as `images/logo.png`.
- Avoid local file paths such as `file:///Users/...`.
- Avoid image URLs that return `403` or require login.

## 10. Send Bulk Email

Before sending, make sure `.env` has:

```env
DRY_RUN=true
```

Run with the unified entry:

```bash
python3 main.py send
```

Or run the script directly:

```bash
python3 src/send_bulk_email.py
```

With `DRY_RUN=true`, this will simulate sending emails without actually sending them.

Expected dry run output:

```text
DRY_RUN mode: True
DRY RUN - would send to: xxx@example.com
```

To send real emails, change `.env`:

```env
DRY_RUN=false
```

Then run:

```bash
python3 main.py send
```

When `DRY_RUN=false`, the script requires manual confirmation.

You must type:

```text
SEND
```

before real emails are sent.

## 11. Unified Command Line Entry

This project supports a unified command line entry through `main.py`.

Available commands:

```bash
python3 main.py check
python3 main.py filter
python3 main.py preview
python3 main.py send
python3 main.py test-send
python3 main.py all
```

Command meanings:

- `check`: check project configuration, required files, send settings, and SMTP settings
- `filter`: read the raw customer CSV and generate the filtered subscriber CSV
- `preview`: generate the HTML email preview
- `test-send`: send the generated HTML email to TEST_TO_EMAIL only
- `send`: send emails or run dry run based on `.env`
- `all`: run `check`, `filter`, `preview`, and `send` in order

Recommended safe command:

```bash
python3 main.py check
```

Run `check` before sending any campaign. It does not send emails. It only checks whether the required files and configuration are ready.

## 12. Recommended Full Run Order

For a normal campaign, first run:

```bash
python3 main.py check
```

This checks:

- `.env`
- raw customer CSV
- campaign JSON
- HTML template
- subscriber CSV
- send settings
- SMTP settings

Then run the full workflow:

```bash
python3 main.py all
```

This will run:

```text
1. Check project configuration
2. Filter subscribed users
3. Generate HTML email preview
4. Run dry run or send emails based on .env
```

You can also run each step separately:

```bash
python3 main.py check
python3 main.py filter
python3 main.py preview
python3 main.py send
```

Recommended safe process:

```text
1. Put the raw customer CSV into data/customers.csv
2. Check .env CSV column settings
3. Run python3 main.py filter
4. Check data/subscribed_only.csv
5. Update campaign.json
6. Run python3 main.py preview
7. Review output/preview.html
8. Set DRY_RUN=true
9. Run python3 main.py send
10. Check dry run output
11. Replace subscriber CSV with internal test emails if needed
12. Set DRY_RUN=false and MAX_SEND_LIMIT=3
13. Run python3 main.py send
14. Type SEND to send test emails
15. Confirm test emails look correct
16. Restore real subscribed_only.csv
17. Get approval
18. Set DRY_RUN=false with the correct MAX_SEND_LIMIT
19. Run python3 main.py send
20. Type SEND to confirm real sending
21. Review output/send_log.csv
22. Set DRY_RUN=true after sending
```

## 13. Sending Log

The sending log is saved to:

```text
output/send_log.csv
```

The log includes:

```csv
time,email,status,error_message
```

Possible statuses:

```text
sent
dry_run
failed
skipped_invalid_email
skipped_duplicate
skipped_previously_sent
```

Use this log to review:

- Which emails were sent
- Which emails failed
- Which emails were skipped
- Why a record failed or was skipped

Successful real sends are also written to:

```text
output/recipient_history.csv
```

This file is used to prevent the same `campaign_name` from being sent to the same email again.

## 15. GitHub Safety

Do not upload real customer CSV files to GitHub.

The `.env` file contains sensitive email credentials and should not be uploaded.

The following files should be ignored by Git:

```text
.env
output/
data/*.csv
```

Sample CSV files are safe to upload:

```text
data/sample_customers.csv
data/sample_subscribers.csv
```

Recommended `.gitignore`:

```gitignore
__pycache__/
*.pyc

.env

output/

data/*.csv
!data/sample_subscribers.csv
!data/sample_customers.csv

.DS_Store
```

Before pushing to GitHub, run:

```bash
git status
```

Make sure these files do not appear:

```text
.env
data/customers.csv
data/subscribed_only.csv
output/preview.html
output/send_log.csv
output/recipient_history.csv
```

If sensitive files appear, stop and fix `.gitignore` before pushing.
